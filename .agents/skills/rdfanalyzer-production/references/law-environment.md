# LAW environment, scheduler, and worker packaging

Read for task discovery, scheduler connection, import failures, portable Python payloads, and common staging helpers. Task-specific inputs and dependencies are in [LAW task routing](law-tasks.md).

## Resolve imports and scheduler configuration

From the checkout root, the setup entry points are:

```bash
source env.sh
source core/python/law/env.sh
law run SkimTask --help
```

These select environments and inspect help; they do not submit a skim. Use the interpreter/environment required by the actual run. [LAW env.sh](../../../../core/python/law/env.sh) sets `PYTHONPATH`, `LAW_HOME`, `LAW_CONFIG_FILE`, and `DATA_PATH`; inspect their resolved values. When no virtual environment is active, it tries the checkout-root `.venv`. [setup_python_env.sh](../../../../core/python/law/setup_python_env.sh) searches `build/python` for a module matching the selected worker interpreter’s extension suffixes.

[law.cfg](../../../../core/python/law/law.cfg) lists default imported task modules and scheduler/job/backend settings. Several modules, including `rucio_tasks`, `dag_tasks`, and `manifest_plot_tasks`, are not listed directly; determine whether another imported module brings the task into scope. Do not assume a Python file existing makes its task family discoverable. For example, `plot_tasks.py` re-exports `ManifestPlotTask`, while source discovery imports Rucio tasks at selected call sites. Preserve the caller's site-specific config and task namespace when diagnosing an unknown task.

[startJobManager.sh](../../../../core/python/law/startJobManager.sh) sources the LAW environment and starts `luigid` bound to loopback on port 8082. That is the Luigi scheduler, separate from a Condor schedd or Dask scheduler. Starting another process is unnecessary for a help/import check. Inspect the existing endpoint and invocation before starting a requested scheduler.

[framework.py](../../../../core/python/law/framework.py) supplies thin `Task`/`PlotTask` bases used by plot tasks. `view_output_plots` is a no-op decorator here; successful execution does not launch a viewer.

## Package the runtime that workers consume

`SkimMixin._root_setup_content` snapshots the marked extension-hook block
through `optional_extensions.render_environment_setup` before LAW relocates
the setup text. Check the rendered text as well as the source `env.sh`:
workers should not need `scripts/extension_env.py` or the extension checkout.
Hook contents enter both prepared execution identities and preflight markers.

For sealed bundles, `PrepareSkimJobs` retains rewritten YAML/text bytes while
building the shared cfg archive, then writes those bytes into each local job.
The cache belongs to that preparation invocation and is filled before worker
threads start. Keep job files independent, preserve archive/local byte parity,
and retain the uncached path for direct callers and uncached dependencies.
Avoid parsing and serializing identical shared YAML for every partition.

[setup_python_env.sh](../../../../core/python/law/setup_python_env.sh) installs packages with `pip --target`, optionally copies `rdfanalyzer*.so`, and writes a tarball with package contents at its root. It is a packaging action that can access the network. Match Python ABI, ROOT, native dependencies and OS to the workers; a tarball of Python packages is not a complete native runtime.

Inspect the selected transfer/bootstrap implementation. [htcondor_bootstrap.sh](../../../../core/python/law/htcondor_bootstrap.sh) picks the first matching tarball and searches the extracted tree for `site-packages` and `bin`. The package builder's flat-root layout does not automatically satisfy that search. Do not claim environment activation from successful extraction; verify the effective worker `PYTHONPATH` and import path. Also distinguish this bootstrap template from scripts generated by [submission_backend.py](../../../../core/python/submission_backend.py).

[transport.py](../../../../core/python/rdfproduction/transport.py) owns shared helpers for path normalization, local-library staging, EOS existence queries, Condor ads/history and single-job submission. `collect_local_shared_libs` filters resolved libraries to the chosen repository root and includes ROOT dictionary sidecars and adjacent headers; it does not bundle every system/CVMFS dependency. Preserve sonames and dictionary resources. Use its query functions as evidence before touching the helpers that remove or submit jobs.

For Dask, inspect `DaskWorkflowProxy.run` in [workflow_executors.py](../../../../core/python/law/workflow_executors.py), task `get_dask_work`, retry classification and branch-marker writes. The local fallback forwards the positive integer `dask_workers` count to `Client(n_workers=...)`, defaulting to one. An external scheduler owns its worker count; nondefault inactive local-count requests receive a task message. Code, task parameters and `law.cfg` options must still be traced separately. [requirements-production.txt](../../../../requirements-production.txt) leaves Dask distributed support optional.

Verification: [ingestion helpers](../../../../core/tests/law/test_ingestion_utils.py), [executors](../../../../core/tests/law/test_workflow_executors.py), [executor parity](../../../../core/tests/law/test_executor_parity.py), and [submission backend](../../../../core/tests/python/test_submission_backend.py). Use help/import and local mocked checks for changes to instructions; a real scheduler or worker smoke test is a separate execution.
